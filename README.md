# โค้ดระบบฟาร์มอัจฉริยะ IoT และการจัดการฐานข้อมูลคลาวด์สำหรับธุรกิจเพาะเลี้ยงพืชอวบน้ำ

| โฟลเดอร์ | ใช้ทำอะไร |
|---|---|
| `firmware/smart_farm/` | เฟิร์มแวร์หลัก (ESP32 หรือ NodeMCU ESP8266): อ่านค่า → ส่งขึ้นคลาวด์ → ควบคุมปั๊มและไฟ |
| `firmware/sensor_test/` | โปรแกรมทดสอบเซ็นเซอร์ รีเลย์ และปรับเทียบเซ็นเซอร์ดิน (ใช้กับ ESP8266) |
| `server/` | REST API (Node.js + Express + MongoDB), Web Dashboard และ AI (Gemini Flash-Lite) |

ลำดับที่แนะนำ: **ตั้งเซิร์ฟเวอร์ (ข้อ 1) → ตั้ง AI (ข้อ 2) → อัปโหลดเฟิร์มแวร์ (ข้อ 3) → สอบเทียบเซ็นเซอร์ (ข้อ 4)**

## การทำงานของระบบ (ตรงกับบทที่ 3)

```
เซ็นเซอร์ (ความชื้นวัสดุปลูก, อุณหภูมิ/ความชื้นอากาศ, แสง)
   │
   ▼
ESP32 / ESP8266 ──ค่าสดทุก 5 วินาที / ข้อมูลทุก 5 นาที──► เซิร์ฟเวอร์ ──► ฐานข้อมูล MongoDB
   ▲  ตัดสินใจรดน้ำและเปิดไฟเองตามเกณฑ์      │
   │                                         ▼
   └──── ค่าเกณฑ์ / คำสั่งจากเว็บ ◄──── Web Dashboard ──(กดขอ)──► Gemini Flash-Lite แนะนำค่าเกณฑ์
รีเลย์ → ปั๊มน้ำ DC 12V, ไฟ LED 12V
```

- **ส่งข้อมูลขึ้นคลาวด์ทุก 5 นาที** (บทที่ 3 การเก็บข้อมูล ข้อ 1.2) แต่ละครั้งมีเลขลำดับ `seq` ไว้คำนวณอัตราการส่งสำเร็จ
- บอร์ดตัดสินใจปั๊มทุก 60 วินาที และส่ง **ค่าสด** พร้อมรับคำสั่งและตัดสินใจไฟทุก 5 วินาที ผ่านการเชื่อมต่อ HTTPS ที่เปิดค้างไว้ (ค่าสดแสดงบน Dashboard เท่านั้น ไม่บันทึกเป็นข้อมูลย้อนหลัง)
- **2 โหมด** เลือกบน Dashboard
  - **ตามเกณฑ์**: ความชื้นต่ำกว่า 30% → เปิดปั๊ม 5 วินาที รอซึม 60 วินาที ทำซ้ำจนถึง 45%
  - **สั่งเอง**: ปั๊มทำงานเฉพาะเมื่อกด "ให้น้ำ 1 รอบ" ไฟเปิดปิดตามปุ่ม
- **AI แนะนำค่าเกณฑ์** (Gemini Flash-Lite): กดปุ่ม "ขอคำแนะนำจาก AI" ในส่วนเกณฑ์ควบคุม เซิร์ฟเวอร์สรุปข้อมูลรายชั่วโมง 24 ชม. และภาพรวม 3 วันล่าสุด
  ให้ AI แนะนำค่าเกณฑ์การให้น้ำและการให้แสง 8 ค่า พร้อมเหตุผล **AI ไม่ได้ควบคุมอุปกรณ์และไม่เปลี่ยนค่าเอง** ผู้ใช้ติ๊กเลือกเฉพาะค่าที่ต้องการ กด "นำค่าที่เลือกไปใส่ในฟอร์ม" แล้วกด "บันทึกเกณฑ์" เอง
  เซิร์ฟเวอร์ตรวจคำตอบ AI ก่อนแสดง (อยู่ในช่วงที่อนุญาต และเรียงลำดับถูกต้อง ไม่เช่นนั้นคงค่าเดิม) และเก็บทุกคำแนะนำไว้ใน collection `ai_suggestions`
- **ชั้นป้องกัน**
  - ห้ามรดเมื่อความชื้นถึง 45% (ปุ่มให้น้ำบนเว็บก็เช่นกัน)
  - ปั๊มเปิดได้ไม่เกิน 20 วินาทีต่อครั้ง (ขีดสุดในบอร์ด) และไม่เกิน 200 วินาทีต่อวัน
  - รดอัตโนมัติรวมเกิน 30 วินาทีแต่ความชื้นขึ้นไม่ถึง 2% → หยุดรดอัตโนมัติ (ล็อก) และแจ้งเตือน
  - อ่านเซ็นเซอร์ไม่ได้ → ตัดรีเลย์ทั้งหมด
  - ต่ำกว่า 20% แจ้งเตือน "แห้งวิกฤต" เกิน 60% แจ้งเตือน "แฉะเกินเกณฑ์"
- **ไฟ LED** (รีเลย์ช่อง 2) เปิดช่วง 06–18 น. เมื่อแสงต่ำกว่า 2,000 lux ปิดเมื่อเกิน 3,000 lux

ค่าทุกตัวแก้ได้ในส่วน "เกณฑ์ควบคุม" บน Dashboard

## 1. ตั้งเซิร์ฟเวอร์และฐานข้อมูล

ต้องมี Node.js 18 ขึ้นไป และฐานข้อมูล MongoDB เลือกอย่างใดอย่างหนึ่ง

- **MongoDB Atlas (ฟรี บนคลาวด์ ตรงกับชื่อโครงการ)**: สมัครที่ mongodb.com/atlas สร้าง Cluster แบบ Free
  สร้างผู้ใช้ฐานข้อมูล ตั้ง Network Access แล้วคัดลอก connection string (`mongodb+srv://...`)
- **ในเครื่องตัวเองด้วย Docker**:

```bash
docker run -d --name smartfarm-mongo -p 27017:27017 -v smartfarm-data:/data/db mongo:7
```

จากนั้น

```bash
cd server
```

```bash
npm install
```

คัดลอก `.env.example` เป็น `.env` แล้วแก้ `MONGODB_URI` และตั้ง `API_KEY` เป็นรหัสลับของตัวเอง

```bash
npm start
```

หน้าจอจะแสดงบรรทัด `ใส่ใน config.h: #define SERVER_URL "http://192.168.x.x:3000"` ให้จดไว้ใช้ในข้อ 3
เปิด Dashboard ได้ที่ `http://localhost:3000`

## 2. ตั้ง AI แนะนำค่าเกณฑ์ (Gemini Flash-Lite)

1. เข้า https://aistudio.google.com/apikey ด้วยบัญชี Google แล้วกด **Create API key** (ใช้ระดับฟรีได้)
2. วาง key ใน `GEMINI_API_KEY` (ในเครื่อง: ไฟล์ `server/.env`, บน Vercel: Environment Variables แล้ว deploy ใหม่)
3. `GEMINI_MODEL` ตั้งไว้เป็น `gemini-3.5-flash-lite` ถ้าต้องการรุ่นอื่นให้แก้ตรงนี้
4. บน Dashboard กด **ขอคำแนะนำจาก AI** ในส่วนเกณฑ์ควบคุม (ใช้เวลาประมาณ 10–30 วินาที ขอได้ห่างกันอย่างน้อย 30 วินาที)

> ห้ามใส่ Gemini API key ในเฟิร์มแวร์หรือหน้าเว็บ key อยู่ที่เซิร์ฟเวอร์เท่านั้น
> ระบบเรียก Gemini เฉพาะตอนผู้ใช้กดขอคำแนะนำ จึงใช้โควตาน้อยมาก

## 3. อัปโหลดเฟิร์มแวร์

1. ติดตั้งบอร์ด
   - ESP8266: Boards Manager URL `https://arduino.esp8266.com/stable/package_esp8266com_index.json` → ติดตั้ง **esp8266**
   - ESP32: ติดตั้ง **esp32 by Espressif Systems** จาก Boards Manager
2. Library Manager ติดตั้ง
   - **BH1750** (Christopher Laws)
   - **ArduinoJson** (เวอร์ชัน 7)
   - **Adafruit BME280 Library** ถ้าใช้ BME280 หรือ **DHT sensor library** (Adafruit) ถ้าใช้ DHT22
3. ถ้าเพิ่ง clone จาก GitHub ให้คัดลอก `firmware/smart_farm/config.example.h` เป็น `config.h` ก่อน (ไฟล์ `config.h` ไม่ขึ้น GitHub เพราะมีรหัส Wi-Fi และ API key) แล้วเปิด `firmware/smart_farm/smart_farm.ino` และแก้แท็บ `config.h`
   - `WIFI_SSID`, `WIFI_PASS` (ใช้ได้เฉพาะ Wi-Fi 2.4 GHz)
   - `SERVER_URL` ตามที่ได้จากข้อ 1
   - `API_KEY` ให้ตรงกับไฟล์ `.env`
   - เลือกเซ็นเซอร์ `TEMP_SENSOR_BME280` หรือ `TEMP_SENSOR_DHT22`
4. Tools → Board เลือก **NodeMCU 1.0 (ESP-12E Module)** หรือ **ESP32 Dev Module** เลือกพอร์ต แล้วกด Upload

ขาต่อ

| อุปกรณ์ | NodeMCU ESP8266 | ESP32 DevKit |
|---|---|---|
| SDA / SCL (BH1750, BME280) | D2 / D1 | GPIO21 / GPIO22 |
| DHT22 (ถ้าใช้) | D7 | GPIO4 |
| เซ็นเซอร์ความชื้นวัสดุปลูก | A0 | GPIO34 |
| รีเลย์ปั๊ม 12V | D5 | GPIO26 |
| รีเลย์ไฟ LED | D6 | GPIO27 |

5. เปิด Serial Monitor ที่ **115200** จะเห็นบรรทัดแบบนี้ทุก 60 วินาที

```
T=28.4C RH=63% Lux=1530 Soil=41% (raw 455) | ปั๊ม=off ไฟ=ON | โหมด=auto threshold | ส่งข้อมูลแล้ว WiFi=ok server=ok
```

| ถ้าเห็น | สาเหตุที่พบบ่อย |
|---|---|
| `bme280: ไม่พบ!` / `BH1750: ไม่พบ!` | สาย SDA/SCL สลับกัน หรือไฟเลี้ยงไม่ใช่ 3.3V |
| `server=ไม่ตอบ` + `code=-1` | IP ใน `SERVER_URL` ผิด, เซิร์ฟเวอร์ไม่ได้รัน หรือ Firewall บล็อก |
| `code=401` | `API_KEY` ใน config.h กับ .env ไม่ตรงกัน |
| รีเลย์ติดตั้งแต่เปิดเครื่อง | เปลี่ยน `RELAY_ACTIVE_LOW` เป็น `false` |

## 4. สอบเทียบเซ็นเซอร์ (บทที่ 3 ข้อ 3.1)

1. **ความชื้นวัสดุปลูก**: อัปโหลด `sensor_test` พิมพ์ `c` จดค่า raw ตอนอยู่ในอากาศ (`SOIL_RAW_DRY`) และตอนจุ่มน้ำถึงขีด (`SOIL_RAW_WET`)
2. **ค่าชดเชย (Offset)**: วางเซ็นเซอร์คู่กับเครื่องมือวัดมาตรฐาน อ่านค่าเทียบกันหลายครั้ง
   แล้วใส่ `TEMP_OFFSET`, `HUM_OFFSET`, `SOIL_OFFSET` = ค่ามาตรฐาน − ค่าเซ็นเซอร์ (เฉลี่ย) จนคลาดเคลื่อนน้อยกว่า 3%
3. **อัตราการไหลของปั๊ม**: กด "ให้น้ำ 1 รอบ" (5 วินาที) ลงถ้วยตวง หารปริมาณ (มล.) ด้วย 5
   แล้วใส่ใน "อัตราการไหลของปั๊ม" บน Dashboard ระบบจะคำนวณปริมาณน้ำที่ใช้เป็นลิตรให้

## 5. นำขึ้นใช้งานจริงบน Vercel + MongoDB Atlas

Vercel รันเซิร์ฟเวอร์เป็น Vercel Function (ไม่มีเครื่องเปิดค้าง) จึงต้องใช้ฐานข้อมูลบนคลาวด์คือ MongoDB Atlas แทน Docker ในเครื่อง
หน้า Dashboard (`server/public/`) ถูกเสิร์ฟผ่าน CDN ของ Vercel ส่วน `/api/*` รันใน `server/server.js`

1. **MongoDB Atlas** (https://cloud.mongodb.com) สร้าง Cluster ฟรี (M0) เลือกภูมิภาค **Singapore**
   - Database Access: สร้างผู้ใช้และรหัสผ่าน
   - Network Access: เพิ่ม `0.0.0.0/0` (Vercel ไม่มี IP คงที่)
   - Connect → Drivers: คัดลอก connection string `mongodb+srv://...`
2. **Vercel**: สร้างโปรเจกต์จากโฟลเดอร์ `code/server` (ผ่าน GitHub หรือ `npx vercel` ในโฟลเดอร์นี้) Root Directory = `code/server`
3. ตั้ง **Environment Variables** ใน Vercel (Settings → Environment Variables): `MONGODB_URI`, `DB_NAME=smartfarm`, `API_KEY` (ค่าเดียวกับ config.h), `GEMINI_API_KEY`, `GEMINI_MODEL` แล้ว Redeploy
4. เปิด `https://<ชื่อโปรเจกต์>.vercel.app` ต้องเห็น Dashboard และ `/api/status` ต้องไม่ขึ้น error
5. แก้ `SERVER_URL` ใน config.h เป็น `"https://<ชื่อโปรเจกต์>.vercel.app"` (ไม่มี / ปิดท้าย) แล้วอัปโหลดเฟิร์มแวร์ใหม่
   Serial Monitor จะแสดง `[HTTPS] ... บัฟเฟอร์รับ 16384 ไบต์` และ `server=ok`

หมายเหตุ
- `vercel.json` ระบุ `"framework": "express"` (ถ้าไม่ระบุ Vercel จะเสิร์ฟแค่หน้าเว็บ และ `/api` จะขึ้น 404) และให้รันที่สิงคโปร์ (`sin1`)
- deploy ใหม่หลังแก้โค้ด: `cd code/server && vercel deploy --prod`
- เพิ่ม/เปลี่ยนค่าลับ: `vercel env add <ชื่อ> production --force` แล้ว deploy ใหม่ ค่าจึงจะมีผล
- ไฟล์ `.env` ไม่ถูกอัปโหลด (`.vercelignore`, `.gitignore`) ค่าลับต้องตั้งใน Vercel เท่านั้น
- ทุกคนที่มีลิงก์ดูข้อมูล เปลี่ยนค่าตั้ง และสั่งงานบน Dashboard ได้โดยไม่ต้องใส่รหัส (ตามที่ผู้ใช้ขอ) ส่วนการส่งข้อมูลจากบอร์ดยังต้องใช้ `API_KEY` จึงปลอมข้อมูลทดลองไม่ได้
- ยังรันในเครื่องได้เหมือนเดิมด้วย `npm start`

## ข้อมูลสำหรับบทที่ 4

ส่วน "สรุปผลการทดลอง 14 วัน" บน Dashboard (หรือ `GET /api/stats?days=14`) คำนวณให้

| ค่า | วิธีคำนวณ |
|---|---|
| อัตราการส่งข้อมูลขึ้นคลาวด์สำเร็จ (%) | จำนวนที่บันทึกได้ ÷ จำนวนที่บอร์ดส่ง (นับจากเลข `seq`) × 100 |
| อัตราการรักษาระดับความชื้นที่เหมาะสม (%) | จำนวนครั้งที่ความชื้นอยู่ระหว่าง "เริ่มให้น้ำ" ถึง "แฉะเกินเกณฑ์" ÷ ทั้งหมด × 100 |
| ภาวะแฉะเกินเกณฑ์ (%) | จำนวนครั้งที่ความชื้นเกิน "แฉะเกินเกณฑ์" (ค่าเริ่มต้น 60%) ÷ ทั้งหมด × 100 |
| ปริมาณน้ำสะสม (ลิตร) | เวลาที่ปั๊มทำงาน × อัตราการไหล รวมทั้งช่วงและแยกรายวัน |
| จำนวนครั้งที่ขอคำแนะนำจาก AI | นับจาก collection `ai_suggestions` (ใช้ประกอบการประเมินโดยผู้เชี่ยวชาญ ว่าคำแนะนำสมเหตุสมผลหรือไม่) |

ดาวน์โหลดข้อมูลดิบเป็น CSV (เปิดด้วย Excel) ได้จากลิงก์บน Dashboard หรือ `GET /api/export.csv?days=14`
ทุกคำแนะนำของ AI (ข้อมูลที่ส่งให้ คำตอบ เหตุผล และสิ่งที่ระบบตรวจแก้) เก็บไว้ใน collection `ai_suggestions`

## API (สำหรับทดสอบด้วย Postman)

| เส้นทาง | ต้องใช้ `x-api-key` | หน้าที่ |
|---|---|---|
| `POST /api/readings` | ✓ | อุปกรณ์ส่งข้อมูล (ทุก 5 นาที) ได้ค่าตั้งและคำสั่งกลับไป |
| `POST /api/device/poll` | ✓ | อุปกรณ์ส่งค่าสด (เก็บทับใน collection `live`) และถามค่าตั้งและคำสั่ง ทุก 5 วินาที (`GET` ยังใช้ได้สำหรับเฟิร์มแวร์รุ่นเก่า) |
| `GET /api/readings?from=&to=&days=&limit=` | | ข้อมูลล่าสุดและย้อนหลัง |
| `GET /api/live` | | ค่าสดล่าสุดและสถานะออนไลน์ (หน้าเว็บเรียกทุก 5 วินาที) |
| `GET /api/status` | | ค่าล่าสุด สถานะออนไลน์ การแจ้งเตือน และ AI ล่าสุด |
| `GET /api/settings` / `PUT /api/settings` | | อ่าน/แก้เกณฑ์และโหมด |
| `POST /api/control` | | `{"device":"pump","action":"pulse"}` หรือ `{"device":"led","action":"on"}` |
| `GET /api/events` | | ประวัติการให้น้ำ คำแนะนำ AI คำสั่ง และข้อผิดพลาด |
| `POST /api/ai/suggest` | | ขอคำแนะนำค่าเกณฑ์จาก AI (ขอได้ห่างกันอย่างน้อย 30 วินาที ไม่เปลี่ยนค่าเอง) |
| `GET /api/ai/suggestions` | | ประวัติคำแนะนำของ AI |
| `GET /api/stats?days=14` | | สถิติสำหรับบทที่ 4 |

## สถานะการทดสอบ (20 พ.ย. 2569)

- **เซิร์ฟเวอร์ (Deploy แล้ว)** ที่ https://smart-farm-iot-six.vercel.app (โปรเจกต์ Vercel `smart-farm-iot`, ฐานข้อมูล Atlas `smartfarm`)
  - ส่งข้อมูล ค่าสดทุก 5 วินาที ถามคำสั่ง ปฏิเสธ key ผิด สถิติ และ CSV ผ่าน
  - หน้าเว็บสั่งงานได้โดยไม่ต้องใส่รหัส ส่วนเส้นทางของบอร์ดยังต้องใช้ `API_KEY`
  - AI แนะนำค่าเกณฑ์: ทดสอบกับ Gemini จำลอง (ตอบถูก, ตอบค่าผิดช่วง/ผิดลำดับ → ระบบคงค่าเดิมและบอกเหตุผล, กดรัว → ปฏิเสธ 429)
    และทดสอบกับ Gemini จริง 1 ครั้ง (ใช้เวลา 20.4 วินาที, 1,841 token, แนะนำคงค่าเดิมทั้ง 8 ค่าพร้อมเหตุผล)
  - ค่าตั้งโหมด AI เดิมถูกเปลี่ยนเป็นโหมดตามเกณฑ์อัตโนมัติ
- **เฟิร์มแวร์**: คอมไพล์ผ่าน (NodeMCU 1.0, RAM 39%) ทดสอบ HTTPS กับ Vercel และค่าสด 5 วินาทีบนบอร์ดจริงแล้ว
  - **ยังไม่ได้อัปโหลด** รุ่นที่มีระบบป้องกันรดไม่หยุดและตัดโหมด AI ออก (บอร์ดรุ่นปัจจุบันยังทำงานกับเซิร์ฟเวอร์ใหม่ได้ตามปกติ)
  - ESP8266 ใช้ Wi-Fi ได้เฉพาะ 2.4 GHz และเครือข่ายแบบเปิดที่ต้องล็อกอินผ่านหน้าเว็บ (captive portal) จะใช้ไม่ได้
- โฟลเดอร์ `../ai/` (โมเดลที่ฝึกเองแล้วฝังในบอร์ด) **ไม่ได้ใช้แล้ว**
